# 执行与验收约定 v1.3.0

本约定约束建站执行和验收；领域细则仍读统一手册。用户当前具体需求和已批准决定优先。不要将不确定性、个人偏好或泛泛风险判断转化为改稿权限。

## 开始时锁定版本和交付范围

记录实际加载的三个Skill路径、VERSION、项目标准版本、参考页面和目标主题/环境。缺少兄弟Skill或旧项目固定旧标准时明确差异；在授权迁移范围内合并新规则，保留原决定与历史，不以新模板覆盖项目数据。不得将“GitHub已更新”当作“本机已使用”。

分别定义本次目标：结构原型、视觉复刻、功能预览或可销售网站；既有目标不可自行降级。缺少真实商品/商业数据时记录阻塞项，并继续其余工作；不要编造交易数据，也不要将禁用CTA算作购买流程通过。

## 严格复刻默认保留，差异需依据

Reference Map为每个模块登记：原文/内容角色、素材和数量、PC/手机布局、默认态、触发态与交互结果、目标实现、用户批准差异ID。只有模块ID/容器数量相同不是复刻完成。

发现疑问时依次做：核对已有授权和来源 → 内部记录具体事实与不确定性 → 在确实影响当前步骤时提出具体差异方案 → 按用户决定执行。未知不等于虚假、不适用或不可使用；“风险”“安全适配”“证据型适配”等笼统标签不能授权替换。确有工具/访问/使用限制时说明准确限制及受影响项，不默默改成别的内容。

不得自行把视频换静态图、评价轮播换生活方式图、结果时间线换使用步骤、删除评论/星级、减少卡片或将原文概括重写。批准新增一个模块不授予修改其他模块的权利。无新增差异授权时保留已批准的复刻目标，继续独立工作；不能靠改分母或改验收目标让任务“通过”。

核实状态和工作解释只记内部文件，不注入网站文案、媒体、无障碍文本或前端数据。检查语义，不仅搜HOLD等关键词：“source merchant”“supplied diagrams”“final specification to confirm”等制作过程解释同样需要检查。原本合理的产品使用/安全说明不因此一律删除。不得编造评论、认证或新增无依据背书；复刻与发布阶段分开处理具体问题。

## 先验证样段，再展开整页

先在实际目标平台做好共享页头、完整首屏、一个媒体密集模块和产品购买区的代表性样段；小范围工作只检查受影响样段。分别在390和1440及发生异常的实际宽度对照参考，记录字体/换行、区块高度、媒体比例/裁切、内容密度、间距、CTA位置、背景与滚动节奏。参考CTA不在首屏时不强制改到首屏；用户选择的目标是比较基准。

关键比例或媒体角色未成立时先修样段再复制整页。无需新增风格投票或对每次修正重复索取确认。视觉可用必须来自实际截图审阅，不能由无横滚、资源计数或Theme Check替代。需要简化或替代时走具体差异流程。

## 在目标页面实测完整路径

交互清单包含参考应有的轮播、视频、菜单、图库、Tab、FAQ、套餐、时间线和表单，不只测试现存控件。记录入口、操作、预期可见结果、实际结果、设备、版本及证据。丢掉原交互后测试剩余按钮全通过，整体仍不能通过。

Shopify迁移后从真实首页逐个点击导航、卡片和CTA到产品/锚点/支持/政策/购物车，核对终点、内容与返回路径。检查所有href/src/srcset及动态配置，识别遗留本地.html路由；直接打开预设路由清单不替代入口测试。真实购买与客服送达只有在对应依赖和测试授权具备时验证，模拟态明确记录在内部。

主题实现按可复用模块拆分section/block和商家需改的schema配置；长页硬编码在一个空settings的section不算“可编辑原生主题”完成。合理自定义代码可以保留，实际维护边界说明清楚。

## 完成结论必须能追溯

分开列出结构语义、视觉还原、交互路径、素材迁移、后台可编辑性及交易/发布结果，每项仅为通过/失败/未验证/有理由的不适用。通过须关联当前版本证据、适用模块与批准差异；后续替换使相关证据失效。

自动检查数字仅证明其覆盖的断言；25/25媒体有文件不证明25/25内容正确。未批准替换、缺失行为、404、未关闭视觉差异或必要证据缺失，均阻止对应范围通过。严禁将同一人主观宣称“保持节奏”当作等价证据。报告实际结果，不能把功能预览、视觉复刻和可销售混为一谈。
