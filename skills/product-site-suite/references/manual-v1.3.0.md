## 一、使用入口

用户负责提供产品线索、选择方向和补充必要经营决定；AI负责研究、整理、设计、实施与内部检查。资料表和审查表由AI维护，不要求用户开工前填完。

| 现在要做什么 | 使用方式 |
|---|---|
| 新建产品网站 | 按第二章建立空间，第三章G0→G1完成研究、方案与初版，再逐步补全并验收 |
| 审查已有网站 | 先确定页面、主题、访问身份和目标阶段，按第三章Q1–Q5取证，使用第五章记录问题；审查本身不授权改站 |
| 严格复刻 | 第三章通用质量＋第四章专项同时适用，先完成参考映射再实现 |
| 只改美术或局部修改 | 保留已有内容与功能，按修改影响选取检查，不重做整个项目 |

### 可直接使用的开工请求

> 使用 $product-project-bootstrap 初始化项目并继续搭建这个产品的网站。产品名称：〔名称或工作名〕；项目文件夹：〔使用者指定的绝对路径〕；产品/参考网址：〔网址〕；已有图片：〔路径或附件，如有〕。先整理产品信息和外观/结构参考，再给出风格卡及完整Home手机/PC方案，选定后落实框架和Home初版，通过少量问答补全网站。任务模式：〔重新设计／严格复刻／只改美术〕。使用本手册作为质量依据，正式发布另按明确授权执行。

只有网址时可以先研究；需要建立产品工作空间时再补用户指定路径与产品名。仅要求初始化时，只建立空间和工作台，不自动开始整站制作。

### 可直接使用的审查请求

> 按本手册审查〔网址或项目路径〕，本次范围是〔页面/主题〕，目标是〔预览审查／发布准备／发布后复核〕。先核对实际版本与访问环境，列出问题、证据、优先级和未验证项，不把无法访问记作通过。若属于严格复刻，参考网址为〔网址〕，同时执行第四章。

### 整体推进顺序

产品线索 → 产品信息文档 → 外观/结构参考包 → 风格卡＋完整Home双端方案 → 选定方向 → 框架＋Home可浏览初版 → 少量问答补全 → 验收 → 在授权范围发布及复核。

严格复刻以已给参考为设计方向，使用第四章映射替代风格探索；只改美术和局部任务沿用已有基准。每轮通常围绕一个主题问1–3个必要问题，尽量给可理解的选择及推荐理由；已有答案复用，不依赖答案的工作继续推进。

## 二、项目空间与工作台

工作空间由 product-project-bootstrap 搭建，建站实施由项目任务推进；目录建立、任务建立、网页实现和正式上线分别记录。

### 项目结构与负责人

| 目录 | 用途 | 负责人 |
|---|---|---|
| 根目录 | AGENTS执行入口、PROJECT-INDEX索引、WORKBENCH-RULES协作规则 | 总台 |
| 00-总工作台 | Brief、事实、决定、状态、任务登记、修改记录、参考映射、请求和交接 | 总台 |
| 01-产品资料 | 原始资料、支持证据、参考网站、素材原件 | 总台 |
| 02-品牌与共享设计 | 唯一视觉基准、Logo、字体、共享素材 | 总台 |
| 03-Home页工作台 | Home计划、文案、设计、素材、修改记录及QA证据 | Home工作台 |
| 04-Product page工作台 | 产品页、购买区计划、文案、素材、修改记录及QA证据 | Product工作台 |
| 05-网站开发 | 集成源码与应用说明；已有源码保留实际路径，不强制迁移 | 总台 |
| 06-QA与发布 | 采用标准、通用验收记录、证据和发布记录 | 总台 |
| 99-归档 | 退役版本及历史材料 | 总台 |

三个持久任务分别命名为“产品名称 网站总工作台”“产品名称 Home页工作台”“产品名称 Product page工作台”。复用项目登记的任务，避免重复创建；已有文件保留，不能用新模板覆盖历史决定。

### 共享修改纪律

1. 接手先读项目索引、状态、事实、视觉基准和自己的Brief；确认实际店铺/主题、版本与文件负责人。
2. 页面工作台只改所属目录。共享导航、页脚、全局样式和集成源码由总台处理；页面任务可在REQUESTS/HANDOFFS新建带角色与日期的独立请求或交接文件，不覆盖他人记录。
3. 总台上传前重新获取远端目标文件，与本次修改基线比较并合并；上传后回读核对，再验证实际页面。交接发布责任后旧负责人停止上传。
4. 项目事实只在FACTS-CLAIMS维护，视觉选择只在VISUAL-BASELINE维护，当前状态只在STATUS维护；其他文件引用，不另造相互竞争的结论。
5. 适用的用户授权持续有效，交接记录其具体范围；创建工作空间本身不授权发布、付款或对外发信。

### 本手册和项目文件的对应

| 本手册内容 | 项目内落点 |
|---|---|
| 第三章通用要求 | QUALITY-STANDARD；PROJECT-BRIEF记录采用版本及差异 |
| 第四章复刻专项 | REFERENCE-MAP，非复刻注明不适用 |
| 第五章记录模板 | FACTS-CLAIMS、CHANGE-RECORD、QA-CHECKLIST、STATUS和HANDOFFS |
| 第六章来源说明 | STANDARD-SOURCES或本手册版本引用 |

本手册可单独阅读，无需依赖上述文件才能理解规则；开展项目后再把规则与实际结果分开保存。已有Skill v1.1项目采用本手册时，由总台登记文档v1.3.0及差异，按需合并；单纯复制本手册不代表所有旧规则已升级。

## 三、统一建设与审查标准

以下沿用v1.1有效条款，补回原引导流程与v1.0的必要细节。G表示阶段，Q表示检查类别；它们是检查编号，不是要求用户填写的表。

### 使用与规则选择

本章维护通用质量要求；通用执行结果使用第五章验收表（项目内QA-CHECKLIST），复刻证据使用第四章（项目内REFERENCE-MAP）。PROJECT-BRIEF 记录本项目采用版本和差异，后续升级需比较影响，不自动改写已确认决定。

用户当前明确要求、后续修正和适用的既有授权优先。项目事实决定公开内容；任务模式决定设计自由度。默认建议不能覆盖已选定的设计或复刻基准。

| 任务模式 | 执行与验收 |
|---|---|
| 新建/重新设计 | 按产品、受众和素材组织内容，可精简重复说服；采用已选方向，没有方向时按下述引导流程探索 |
| 只改美术 | 保留信息、模块顺序及行为；只修改授权的视觉部分；检查相关功能没有回归 |
| 严格复刻 | 先通过 REFERENCE-MAP 的编码前检查；按参考双端结构、视觉、交互实现，通用优化建议不授权删减、重排或隐藏模块 |
| 局部修改/现站审查 | 根据影响范围选用检查；不自动重建整站、重做风格或创建任务 |

参考内容无依据时处理具体内容，不能默默删除容器、折叠整组卡片或虚构证据。草稿可记录待补；公开版本必须解决未核实承诺和占位。必要设计差异先记录具体前后方案，已有授权直接执行，无授权只询问该差异，继续无关工作。

### G0：引导式开工与工作空间

- 用户提供产品/参考网址及已有素材即可开始研究，不要求填写长表。创建工作空间需要用户给定路径和产品名（可用明确的工作名），不自行猜测项目根目录。
- AI整理产品信息文档和事实台账：定义、受众、场景、规格、限制、款式、包装、用法、购买顾虑及来源；能查到的信息不让用户重复收集。
- 收集外观/结构参考包和可浏览图板：正侧背、接口材质、尺寸比例、包装、款式、来源及可发布使用权。固定轮廓、比例、标志、按键和接口；缺少内部结构资料时不用生成图冒充实物拆解。
- 商业信息如价格、物流、政策暂缺可继续内部设计，列为后续依赖；产品身份冲突仅阻止依赖该身份的部分。
- 默认面向 Shopify 单品/少量产品、欧美英语、移动端优先、适度动效；用户给定平台、市场或风格时直接替换。实际配送国家必须单独核实，不能将欧美作为统一法律区域。

### G1：视觉方案与初版

### Logo：名称、设计、确认与应用

- 品牌名/Logo文字只确定拼写，不代表图形、字形、字体、配色、组合或最终资产已确定。“开始做网站”、选定网站风格或采用参考站，也不等于选定 Logo。
- 先读取已有决定：用户明确指定某个文件或方案作为正式 Logo 时直接沿用，不重新要求设计或确认；仅上传图片但用途不明时，只澄清它是参考、候选还是正式资产，不自动定稿。
- 只有名称、尚无正式 Logo 时，将 Logo 设计纳入已授权的网站设计阶段：结合品牌与应用场景制作可查看的候选方案（默认 2–3 个，用户数量优先），说明区别并推荐，然后让用户选定。不能只给提示词、把普通排字默认为定稿，或让页面风格选择代替 Logo 选择。
- 在 VISUAL-BASELINE 分别记录品牌名称状态、Logo状态（待设计/候选待选/已选定待校样/可应用）、候选及选定文件版本、用户选择依据、应用范围和校样结果。没有对应文件与选择依据，不可标记正式 Logo 已确定。
- 选定后先展示适用位置的校样：桌面/手机页头的清晰度、比例、留白、裁切与背景对比；实际需要包装或产品图时，再核对这些应用。通过后才批量制作正式品牌素材或将其应用到页面。一次明确选择可覆盖已展示的方案与校样，无须机械地分两轮确认；新改图形、字形或配色则重新展示变更。
- 待选期间继续研究、文案、页面结构和不依赖 Logo 的设计；内部布局可用明确标注的文字占位。候选 Logo 的应用效果只作为待选校样，不能冒充正式资产、批量替换产品/包装图或上传为正式页面素材。缺少设计工具仅阻塞依赖步骤，记录缺口，不假装设计完成。
- 用户明确要求沿用纯文字标、临时标或跳过设计时遵从，记录具体授权及适用范围；不能从“开始做”推定该例外。
- 发现已经跳过设计时，盘点受影响的图片和页面，标记候选/待替换及是否上传；不要仅回填状态就称问题已修复。按选定资产修正受影响项并复核，未授权的线上修改不执行。

- 已有选定风格则复用，不重新要求选择；严格复刻不探索替代风格。
- 新方向默认给 2–3 张实质不同的可视风格卡并推荐；用户明确数量优先。首轮推荐方向至少一套从导航到页脚的完整 Home 手机/PC 可视方案，不只首屏。用户选择另一方向时先调整整页方案。
- 风格卡记录色彩、字体层级、图标、圆角、间距、摄影光线、产品比例、素材规则及动效；具体选择唯一维护在 VISUAL-BASELINE。
- 各区块写明目的、英文核心文案、素材、布局、触发与回退；手机单独确定顺序、裁切、横滑/堆叠、导航和购买入口。
- 选定后在已授权范围落实全站框架和可浏览 Home 初版，再以每轮通常 1–3 个问题补充产品页、购买区、套餐、运营与发布信息。问题只问尚缺且影响结果的内容，不再次询问是否开始已授权工作。

### Q1：页面及状态覆盖

完整商品站计划至少包含独立 Home、产品详情、Support、品牌404，销售阶段包含政策、购物车和结账路径。Home 初版是中间里程碑，不是整站完成。

| 页面/状态 | 核对要点 |
|---|---|
| Home | 产品、用途、目标人群与下一步清楚；主要行动、场景、支持入口；复刻以参考顺序为准 |
| Product | 图库、用途、规格、包含物、用法、FAQ、价格币种、款式套餐、库存/预售、配送退换摘要和购买入口 |
| Support | 真实联系渠道、上手及排障信息、表单校验/成功/失败；显示、提交及送达分别验证 |
| 政策 | 退换、隐私、条款、配送、联系信息；法律声明按市场评估适用性。正文与入口真实，平台有政策字段时核对实际字段 |
| Cart/抽屉 | 所有已实现入口、数量修改/删除/空车、错误恢复、金额费用及结账；刷新后状态一致 |
| Checkout | 地址市场、配送费、税费、优惠、总额和可用支付；实际支付及成功/失败状态只有测试后可称通过 |
| 404 | 不存在的普通、产品、Page路径；正确404状态、统一品牌、有效恢复入口、无示例商品 |
| 其他 | 多品集合必测；搜索、账户、订单查询、密码页、营销页、应用依实际启用与范围核对，不为凑数量建空页 |

独立路由须能直接访问和刷新；首页锚点和替代 view 预览不代表正式产品/Support路由完成。未开售状态可以真实显示，不编造可购买性。

FAQ/使用指南内容应回答购买与使用障碍，可融入产品页；关于品牌按需提供真实背景，不编造创业故事。搜索启用时检查有结果、无结果、错拼及键盘操作；集合页检查缺货与无结果；账户/订单查询检查访问和找回流程。

### Q2：事实、素材与全站一致性

- 规格、认证、评价、销量、效果图、数字、专业背书引用 FACTS-CLAIMS；来源署名不证明本商品疗效。示意素材不可伪装真实客户经历。
- 价格/库存/款式/套餐以真实绑定为准；图、选择、每件款式、折扣、库存扣减、购物车与结账一致。
- 公告、商品、FAQ、购物车、政策、结账的运费和时效一致；预计发出日期与运输时间分开，退货与保修定义清楚。
- 核对本品牌外链、邮箱、地址、社交、默认配置、静态模板和生成器，不能恢复参考店身份或占位。公开邮箱、收件配置、发件配置、DNS和送达分别记录。
- 产品几何、材质、接口、包装与实际交付一致；文字和按钮在页面中实现，不烘焙进图。媒体托管与使用权分别核实。

硬件商品要在购买前说明必要的供电、安装或App依赖、实际包含物和限制；客服回复时间等承诺也须有依据。

### Q3：视觉、适配与可访问性

- 各页使用同一视觉基准，检查实际字体加载、排版、层级、媒体节奏及关键行动。局部方案不能替代全页评审。
- 每类模板完整检查实际390和1440视口；320、430、768、1024、1920重点查首屏、购买区、表格、弹层、导航、页脚，可按目标设备调整并记录。工具请求宽度与实际宽度分别记录。
- 发布审查覆盖目标浏览器及 iOS Safari/Android Chrome 真机；没有设备写未验证，模拟视口不可冒充真机。
- 无意外整页横滚、截字、遮挡；轮播局部滑动。关键控件建议44×44 CSS px；正文建议16–18px、行高1.5–1.7，这些为设计建议，不能据此擅改复刻。
- 普通文本对比度至少4.5:1、大字3:1、关键控件边界/状态3:1；不只靠颜色表意。键盘菜单/选款/FAQ/购物车可操作，弹层焦点返回，200%放大仍可用，提供所需替代文本和字幕，错误提示关联对应字段。
- 检查资源失败、低速网络及视频无法播放的回退。复刻与可访问性要求冲突时先找保真实现，确需视觉差异记录并处理，不将任一项假记通过。

新设计可用5秒理解检查产品、用途和下一步是否清楚。TICKEY仅作为产品主体、用途演示、章节层级与选购清晰度的偏好参考，不固定深色、霓虹或电子产品布局；复刻以用户提供的参考为准。

### Q4：动效与性能

- 动效级别可用M0（静态与操作反馈）、M1（轻入场与局部演示，默认）、M2（复杂叙事，另定预算）。默认轻量动效，不强迫每屏动画；保留原生滚动、即时操作反馈，连续点击不锁死或重复加购。
- 建议按钮120–200ms、折叠180–300ms、入场300–600ms；已有设计/复刻基准优先。脚本失败不能永久隐藏正文。
- 视频有封面、失败回退、静音内联自动播放；适当暂停离屏视频；循环/轮播可暂停。尊重减少动态偏好，保留必要功能。
- 流畅度通过操作与录制检查，截图不能证明无卡顿。记录设备/网络/版本和测量方式；关键购买信息不依赖精确滚动位置，轮播不自动切走用户正在操作的内容。
- 性能目标：真实数据p75 LCP≤2.5秒、INP≤200ms、CLS≤0.1，手机桌面分开；缺少实地数据时报告实验室结果和实地待补，代理指标不能冒充INP。
- 初始预算建议手机首图≤250KB、桌面≤500KB、字体总量≤200KB；视频另计。超预算依据收益和实测判断，不机械牺牲清晰度。

### Q5：集成、运营与维护

- 建立页面/共享组件/主题/A-B版本影响清单；总台上传前重新读取最新远端并合并，定向上传后回读，再检查实际前台。文件一致不证明布局与购买正确。
- 同时核对独立模板和动态刷新/选款后的内容；A/B测试不可改快照时记录缺口，不擅自结束测试或改变分流。
- 检查标题、描述、主标题、canonical、分享图、索引策略与结构化数据一致性。统计/同意管理按确认市场规划，不为测试擅装追踪。至少规划浏览、选款、加购、结账、购买事件，但规划不等于已经接通。
- 支持表单真实发送和付款按已有授权范围执行；没有授权时记未验证，不伪造结果。
- 交付可编辑源文件、素材来源、依赖、准确环境/版本、维护责任和回滚位置；不擅改已有开发目录、Live或Git状态。

### G2–G4：验收与放行

QA-CHECKLIST 是唯一通用验收结果表；复刻额外填写 REFERENCE-MAP 的逐端差异与指标，通过检查ID关联，不复制相同结果。STATUS 汇总并链接证据。

| 阶段 | 允许表述与必需证据 |
|---|---|
| G0资料与空间 | 文件/工作台创建和产品输入状态；不代表已设计 |
| G1设计与Home初版 | Logo选定与适用位置校样（或明确例外）、选定方向、完整双端Home和可浏览初版；其余页面进度明确 |
| G2完整预览 | 范围内路由、内容、交互及启用的商品绑定；未接通事项清楚，复刻需独立结果 |
| G3发布准备 | 当前版本适用质量项、内容政策、功能、设备、性能证据；目标与回滚；核心未知不算通过 |
| G4发布后 | 明确授权、正确Live版本和匿名入口复核；密码/预览/登录限制、结账入口和实际支付分别报告 |

检查状态统一：通过 / 失败 / 未验证 / 不适用（附理由）。P0为无法访问/购买、价格款式错误等关键故障；P1为核心布局、关键政策及重大无依据承诺；P2为不影响理解交易的局部问题。当前发布范围P0/P1及核心未验证阻止放行；P2记录责任与期限。实地性能无数据按Q4明确条件报告，不伪造通过。

仅针对改动影响范围复验，无关且仍有效的证据可复用；修改后受影响证据立即标待验证。通用功能/视觉、复刻还原度、远端同步、GitHub、Live、交易状态互不替代。权重评分不得抵消关键失败。

## 四、严格复刻专项

通用质量仍执行第三章；仅严格复刻使用本章，非复刻注明不适用。

### 编码前 Reference Map Gate

| 稳定页面/模块ID | 参考URL及截图/提取来源 | 桌面顺序/布局/可见性/交互 | 手机顺序/布局/可见性/交互 | 素材及事实ID | COPY/ADAPT/HOLD | 目标实现位置 | 证据缺口 |
|---|---|---|---|---|---|---|---|

- Gate：未验证。通过须覆盖本次范围全部页面、访客可见语义模块和关键交互，双端证据独立；代码文件数不代替模块数。
- 未取得参考不等于参考没有；补查后仍缺证据的依赖部分阻塞，不猜测响应式，不阻止无关工作。完整站已确定范围内、确认参考缺少的整页可按统一品牌规格补建，单列且不称参考一致。
- 调用MiroMiro时先确认实际能力、访问、额度；dashboard不是已验证的提取API。提取可能截断，字体、懒加载、视频和交互须回到真实页面补查。

### 内容状态

COPY：允许使用且内容适用于目标项目。ADAPT：按已确认品牌/事实与素材边界适配。HOLD：缺少事实、素材或权限；保留结构待补，不伪造内容。内容状态、用户授权状态和QA结果分开。

HOLD不自动通过，也不从应验总数删除。草稿占位须明确当前用途；空壳、零高度、不可达或缺整组内容不算完整。公开前解决HOLD及未核实公开承诺，必要设计差异按下表处理。

### 严格复刻：素材迁移与独立交付

严格复刻默认保留参考素材的内容与对应关系，并将可使用的素材迁移到目标项目控制的存储。原站URL是来源证据，不是交付页面的运行时素材地址；参考站使用第三方CDN也不能直接沿用其资源链接。目标商店自己的 Shopify CDN 属于目标存储，不要求与页面同域。

#### 获取、迁移与替换

- 逐模块盘点视频、封面、图片及响应式版本、音频、字幕、字体、SVG、动画和CSS背景等实际依赖。记录来源URL、模块ID、使用依据、下载状态、本地路径、目标存储地址及替换位置。已有使用授权直接沿用；可访问不等于可随意使用，明确缺少必要权限时标记HOLD，不绕过访问限制或DRM。
- 在工具允许的获取方式下下载实际文件到项目资产目录，核实格式、大小及可解码性；原始文件保留校验值。再上传到目标商店Files、主题assets或用户控制的CDN，按文件类型、大小与平台限制选择存储，不能把所有视频一律塞进主题assets。
- 视频不能只复制网页地址、blob URL或临时签名链接。若为HLS/DASH，核实播放清单、分片及音轨/字幕依赖全部迁移，或取得可使用的独立文件；只搬清单却仍请求原站分片不算完成。无法可靠获取时记录阻塞，不冒充已迁移。
- 替换所有实际加载路径，包括video/source、poster、track、srcset、CSS url、懒加载属性、主题设置/JSON、脚本动态注入及桌面/手机独立素材。保留原素材与目标素材的一一映射；不得用自制测试视频或不同内容冒充原素材复刻。必要转码或压缩记录原因并核对时长、画面、比例、声音及视觉影响。
- 没有正式素材时，保留模块结构并标记HOLD；可用明确标注的内部测试素材验证布局，但该模块的素材复刻仍未完成。不能默认隐藏、删除模块或改用原创素材来消除缺口；用户明确同意替代/删减时记入Deviation Log，验收为符合批准目标。
- 参考站媒体外链仅可用于明确标记的临时内部比对，不得作为交付草稿或正式主题的完成方案。用户明确要求保留第三方嵌入或授权外链时记录具体例外、依赖及验收范围，不宣称全部素材已独立迁移。

#### 验证与交付门槛

- 先扫描最终源文件/配置中的参考站及其媒体域名，区分来源记录、正常导航链接与运行时素材请求；再在实际桌面和手机页面触发懒加载、播放与交互，核查网络请求目的地。静态无原域名、上传成功或HTTP 200均不能单独证明迁移完成。
- 视频验证实际画面推进、封面、尺寸/比例/裁切、循环、静音、自动播放、playsinline、控件、点击行为及按需加载，按参考实际行为核对；实际需要时验证音轨、字幕、拖动和全屏。自动播放受浏览器策略限制时记录实际结果，不能伪称通过。
- 不删除源文件，在目标预览中阻断已识别的参考站媒体域名，清除缓存或使用未缓存环境，再触发相关页面状态，验证仍能加载/播放。无法执行网络阻断或真实播放检查时标记未验证，不将文件校验代替运行验收。
- 资产迁移完成须有目标可用地址、替换覆盖和运行证据：本次应迁移素材缺失数=0，未批准的参考站运行时素材依赖=0，相关双端测试通过。批准例外单列，不从清单悄悄删除；素材HOLD阻止该范围宣称严格复刻完成，独立工作可继续。
- 若发现已热链，先列出受影响页面/主题及依赖，按已有授权迁移、替换、回读并复验；不因修改规则就声称项目已修好，不擅自修改未授权的线上主题。

### 严格复刻评论：页面内容与内部核实分开

- 复刻阶段保留参考评论模块的内容、结构、数量、内容密度和交互。未核实评论来源或归属，不等于评论虚假或不适用，也不授予删除、清空、改写、折叠或隐藏模块的权限。不能擅自把评论替换为“待提供”。
- “参考内容”“归属待核实”“未核实”“待提供”、HOLD等工作状态仅记录在内部FACTS-CLAIMS、REFERENCE-MAP或验收记录，不添加到网站文案、卡片、弹窗、提示、图片或用户可访问的无障碍文本中。不要把内部记录直接注入主题、公开JSON、结构化数据或前端配置。内部状态记录不得改变页面呈现；此前“草稿须标明用途”等规则在评论场景中指内部台账，不要求页面标签。
- 内部记录原评论来源、所评产品、可取得的证据、当前核实状态及待决问题；没有证据时只记未知，不自行判定。不得编造评论，也不得新增或改写成未经支持的“本品牌客户”“已验证购买”、销量、评分总数等背书；同样不能把这些无依据身份写入SEO/评论结构化数据。
- 复刻预览与公开发布分别验收：保持参考呈现不等于核实真实客户归属。确有影响公开发布的归属、真实性或使用问题时，在任务对话中给出具体内容、依据和可执行方案，与用户讨论；不要先在网站上加提示或自行改内容。已有明确决定直接沿用，新增差异记录Deviation Log。仅缺少信息不强制整站整改，但不能把尚未解决的问题宣称已核实或发布就绪。
- 用户不希望网站显示内部核实信息，应遵从；这不等于允许将其他品牌评价冒充本品牌真实客户反馈。需要调整的具体内容按用户明确决定执行，保留未经授权不修改的边界。
- 检查结果分别记录：评论内容/数量/交互与批准目标一致、页面没有擅自加入的内部状态文案、没有新增无依据背书、待决发布项未被误报为通过。规则更新本身不代表现有页面已修复。

### 统一后的冲突处理

| 冲突 | 统一处理 |
|---|---|
| 先填完整输入表 vs 引导式开工 | 内部表由AI填；用户只补必要问题；建目录仍需用户路径 |
| 只交首屏/代表区块 vs 完整Home方案 | 新方向首轮含完整手机/PC Home；局部修改及严格复刻不强制探索风格 |
| 固定四套风格 vs 最新2–3套 | 默认2–3；用户数量优先，已有选定方案不重做 |
| 精简重复内容 vs 保留参考结构 | 原创按信息价值组织；复刻不自行删改，差异按已有授权或具体确认落实 |
| 隐藏无证据区块 vs 保留参考容器 | 复刻草稿按HOLD处理内容与容器；公开前解决，空壳不算完整；不伪造证据 |
| 根目录状态文件 vs 总台STATUS | bootstrap项目唯一状态在00-总工作台/STATUS.md；根索引引用它 |
| 通用建议数值 vs 参考设计 | 建议不授权设计变更；记录冲突及保真实现/获准差异，质量失败不能静默豁免 |
| 等资料齐全再实施 vs 持续推进 | 只阻止依赖缺失信息的部分，先做研究/视觉/内部预览 |
| 旧检查表打勾 vs 明确验证边界 | 通用结果只在QA-CHECKLIST记录；复刻专用证据通过ID关联；失败与未验证不算完成 |

不移植历史店铺价格、主题ID、政策、联系方式、测试结果和账号授权。MiroMiro入口不等于提取API；复刻需要时核对现有工具、访问与额度，提取结果关联模块ID，缺证据不能猜。
