# 实际工作流程

本文件仅在用户明确分配研究、设计、开发、上传、发布或 QA 工作后使用；项目初始化时不执行以下阶段。

## 1. 建立基线

总台核实真实开发目录、商店、域名、主题角色/ID、仓库分支、已有用户授权和当前负责人。技术位置只在 `PROJECT-INDEX.md` 维护，`STATUS.md` 引用它。已有源码保留原位置。

## 2. 确认任务模式

在 `PROJECT-BRIEF.md` 记录本次范围和模式：严格复刻、只改美术或重新设计。用户已明确时直接记录，不自行切换模式。

- 严格复刻：使用 `REFERENCE-MAP.md` 建立双端模块和交互映射。
- 只改美术：保留已有内容、信息结构和行为，只修改授权的表现部分。
- 重新设计：确认目标、内容范围和视觉方向后实施。

## 3. 分配精确目标

各工作台在自己的 `CHANGE-RECORD.md` 声明文件、远端目标、环境/版本、基线、负责人和授权。共享或重叠目标通过 `REQUESTS` 指定唯一负责人。

## 4. 实施与验证

仅处理已分配范围。远端写入前读取最新目标并合并，采用精确上传，上传后回读并检查实际桌面和手机页面。适用质量要求按 `QUALITY-STANDARD.md` 相关章节执行，结果写入唯一的 `QA-CHECKLIST.md`。

## 5. 交接

实际负责人记录修改文件、环境/版本、基线、回读、证据、遗留项和接手人。总台同步 `STATUS.md`、跨页影响和最终放行状态，不重复执行页面工作台已经验证的同一批操作。

Logo 的名称、候选、选择、校样和应用规则只在 `06-QA与发布/QUALITY-STANDARD.md` 的 Logo 章节维护；本文件不复制该规则。
