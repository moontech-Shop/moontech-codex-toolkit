# 严格复刻专用映射与验收 v1.2

依据复刻工作流v1.7正文整合。仅严格复刻必填；其他模式在PROJECT-BRIEF标记不适用。通用质量执行QUALITY-STANDARD，结果链接QA-CHECKLIST；本文件仅维护参考、设计偏差、逐端diff及复刻指标。

## 编码前 Reference Map Gate

| 稳定页面/模块ID | 参考URL及截图/提取来源 | 桌面顺序/布局/可见性/交互 | 手机顺序/布局/可见性/交互 | 素材及事实ID | COPY/ADAPT/HOLD | 目标实现位置 | 证据缺口 |
|---|---|---|---|---|---|---|---|

- Gate：未验证。通过须覆盖本次范围全部页面、访客可见语义模块和关键交互，双端证据独立；代码文件数不代替模块数。
- 未取得参考不等于参考没有；补查后仍缺证据的依赖部分阻塞，不猜测响应式，不阻止无关工作。完整站已确定范围内、确认参考缺少的整页可按统一品牌规格补建，单列且不称参考一致。
- 调用MiroMiro时先确认实际能力、访问、额度；dashboard不是已验证的提取API。提取可能截断，字体、懒加载、视频和交互须回到真实页面补查。

## 内容状态

COPY：允许使用且内容适用于目标项目。ADAPT：按已确认品牌/事实与素材边界适配。HOLD：缺少事实、素材或权限；保留结构待补，不伪造内容。内容状态、用户授权状态和QA结果分开。

HOLD不自动通过，也不从应验总数删除。草稿占位须明确当前用途；空壳、零高度、不可达或缺整组内容不算完整。公开前解决HOLD及未核实公开承诺，必要设计差异按下表处理。

## Deviation Log（唯一设计偏差表）

| 差异ID/模块/设备/版本 | 原参考→具体目标 | 类别/原因 | 数量/高度/顺序/相邻模块/交互影响 | 处置与内容状态 | 用户授权原话/时间/范围 | 状态/负责人 | 双端证据/回退点 |
|---|---|---|---|---|---|---|---|

状态：拟议 / 已批准 / 拒绝 / 已实施 / 已验证。记录原因不等于获准；已有明确授权不重复问。意外偏差可直接修回基准。其他设计差异先完成具体可审方案与无关工作，再询问缺少的授权；不能先改正式目标再补记录。

原参考ID及顺序保留，批准增删重排单列。CHANGE-RECORD只引用本表差异ID，不维护第二份授权状态。批准变更验收称“符合批准目标”，不称原参考零差异。

- Technical QA：未验证（引用QA-CHECKLIST的当前检查ID和版本）
- Replication QA：未验证（本表证据）
- 技术通过但复刻未通过：只称功能完成、复刻未完成；反之同理。
- 两轨通过后仅声明当前范围复刻完成，另列批准差异、适配/补建及发布状态。缺少必测证据不得总通过。
- 后续改动使受影响diff失效，重新标待验证并回归相邻布局、共享引用；有效的无关证据可以保留。
