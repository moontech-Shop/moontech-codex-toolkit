# 工作台协作规则

## 写入边界

| 工作台 | 可直接写入 | 只读依赖 |
|---|---|---|
| 网站总工作台 | 根目录协调文件；`00`、`01`、`02`、`05`、`06` | `03`、`04` 的状态与交付物 |
| Home页工作台 | `03-Home页工作台` | 根目录、`00`、`01`、`02` |
| Product page工作台 | `04-Product page工作台` | 根目录、`00`、`01`、`02` |

页面工作台如需修改导航、页脚、全局样式、共享组件、主题设置或其他共享文件，先在 `00-总工作台/REQUESTS` 新建请求，由网站总工作台协调。

## 事实与声明

页面工作台可在 REQUESTS、HANDOFFS 新建带角色和时间的独立文件，不覆盖他人记录；总台维护状态、事实、视觉基准和共享源码。总台上传前获取远端最新目标文件并合并，上传后回读及前台验证。当前发布负责人记入修改记录，交接后旧负责人停止上传。

- 未经证据支持的规格、认证、评价、效果、价格、库存、配送、退换、保修和医学/性能声明一律标记为 `待确认`。
- 供应商或营销材料中的说法不能自动视为已核实事实。
- 任何进入页面的关键声明，都应能追溯到 `00-总工作台/FACTS-CLAIMS.md`。

## 状态边界

- 本地文件完成、页面预览完成、Shopify 预览、GitHub 同步、Live 发布、可正常交易是不同状态。
- 未得到明确授权，不发布 Live theme、不推送 Git、不发送外部消息、不改动生产配置。
- 技术检查通过不等于视觉复刻或商业上线验收通过。
- 适用的已有用户授权持续有效，交接记录其范围，不因切换工作台重复确认。必要信息缺失只阻止依赖该信息的工作。

## 交接格式

每次重要交接写明：

1. 完成了什么。
2. 修改了哪些文件。
3. 依据了哪些已核实事实。
4. 尚有哪些待确认项或风险。
5. 下一工作台需要做什么。
